Release unnecessary complexity in the subject. When `$ARGUMENTS` is non-empty, that is the subject. Otherwise use what is already in front of you: the design, the diff, the explanation, the plan, the passage.

Read it before you judge it. Do not edit, implement, or plan implementation unless the user asks in this turn.

Unnecessary complexity is one product:

complexity = power asymmetry × path dependency × level of abstraction

The factors grow on their own as the work answers ordinary problems. Release means refactoring them back to the minimum the work requires. The subject stays as rich as it is. A release is a shift of view: the same facts, a simpler account, and more explanatory power, as a heliocentric account explains the same sky without the epicycles. A change that only makes the subject smaller, and explains less, is a reduction. Name it as a reduction and leave it off the release list.

**Power.** Whoever meets the work brings different needs and different capacities. That asymmetry stays generative while they can negotiate it. It escalates when a role is fixed ahead of the work and the work must pass through that person. Left alone, ownership concentrates until the whole is too big to fail, too big to know, and too big to fix, while local facts stay too small to detect. Release by letting the role follow the negotiation.

**Path.** Path is the order the work must pass through. A role dependency sends the flow through a particular person. A route dependency ties tasks to each other's timing, shape, and feedback, and locks one outcome before the work has been done. Release by letting the people doing the work redesign the flow, and by keeping more than one next step open. Where the dependency is a role, describe the place of the work instead: what is happening here, what good work looks like, which tasks, and which values.

**Abstraction.** Calling the subject a system is a choice of frame, and each higher frame inherits the lower one's assumptions: what counts as active, where the boundary is drawn, which kind of cause is assumed, and whether the description stands outside the thing. Use the lowest frame that still supports the decision and the action. A higher frame chosen because it feels more complete is the escalation. A frame that only moves the complexity into another layer has not released it.

## Output

1. **Subject** — what you examined
2. **Product** — for power, path, and abstraction, the concrete form of whatever sits above the minimum the work requires. If a factor is already at that minimum, say so.
3. **Release** — each shift of view: the richness it keeps, the layer it drops, and what it explains that the heavier account could not. A shrinkage with no gain in explanation is a reduction. Name it and leave it off this list.
4. **Still required** — the asymmetry, path, or abstraction the work still needs

Do not finish on a list of deletions.
