# Attractor Protocol

Living systems intervention workflow. Gestures are hypotheses. Implementation is testing. Learning is the goal, not shipping.

Cognition is motion in co-variant relations. The same pattern runs at two scales:

1. **Exploration.** Cognitive motion: asking questions, challenging assumptions, following threads, until there is a coherent schema in thinking space. Always available.
2. **Implementation.** System motion: creating change, observing co-variances, until there is a coherent schema in the system.

The boundary is epistemic, not procedural. Exploration continues until a falsifiable claim emerges. Then motion shifts from thinking to the system. Both modes establish structure by observing what co-varies with the motion.

```text
EXPLORATION          IMPLEMENTATION           LEARNING
(cognitive motion) → (system motion)      → (schema)
explore              gesture
(always available)   contact-test
                     design
                     tasks (motion)
                     evidence (optional)
```

Transition: when the claim becomes falsifiable, motion shifts from thinking to the system. Result: a coherent schema, established through accumulated co-variances.

Write one document per step, using that step's reference. Read the reference before writing the document. Use its headings, in its order. These documents are the whole record.

## Workflow

1. No claim yet: read [references/explore.md](references/explore.md) and write that document. Stay there until its exit is met. Skip this step when a claim already exists.
2. Read [references/gesture.md](references/gesture.md) and write the gesture.
3. Read [references/contact-test.md](references/contact-test.md) and write the contact test. Do not change the system until "What would falsify this claim?", "How will we check?", and "When will we check?" are filled. A feedback gesture does not change the system.
4. Read [references/design.md](references/design.md). Write the full document when the change touches several parts, adds a dependency, changes how data is stored, or carries a security, performance, or migration risk. Otherwise write Approach only.
5. Read [references/tasks.md](references/tasks.md) and write the tasks. Then do them.
6. Evidence is optional. When you write it, do so at the contact test's date or condition. Read [references/evidence.md](references/evidence.md) first. Learning is the schema that cohered, not a ship.

Put the documents where the user is already keeping this work. If they have not named a place, keep them in the conversation.
